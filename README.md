# GaragePulse Mobile

Android and iOS client for GaragePulse, a multi-tenant garage/workshop CRM.
Job cards, estimations, invoicing, customers, vehicles, staff and dashboards on
the shop floor.

**Stack:** React Native 0.81 · Expo 54 · TypeScript · React Navigation 7 ·
Axios · AsyncStorage · Jest + React Native Testing Library

Package id: `com.dctechs.garagepulse` ·
[Play Store listing](https://play.google.com/store/apps/details?id=com.dctechs.garagepulse)

Companion repositories: [`garageCrm-be`](https://github.com/Dins2344/garageCrm-be)
(API) and [`garageCrm-fe`](https://github.com/Dins2344/garageCrm-fe) (web).
All three deploy independently.

---

## Prerequisites

- **Node 20** and **npm 10** — pinned in `.nvmrc` and `engines`. A lock file
  generated by a newer npm will fail CI's `npm ci`, so run `nvm use` first.
- **Expo Go** on a phone for day-to-day work, or Android Studio / Xcode for
  native builds.
- A running **GaragePulse API** (see `garageCrm-be`), or a deployed one.

## Getting started

```bash
nvm use          # Node 20
npm ci           # exact dependency install
npm start        # Expo dev server, then scan the QR code with Expo Go
```

Create `.env.local` before starting:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.5:5000/api
EXPO_PUBLIC_WEB_APP_URL=http://192.168.1.5:3000/home
```

> **Use your machine's LAN IP, not `localhost`.** On a phone, `localhost` means
> the phone itself, so the app will fail to reach an API running on your
> computer. Find it with `ipconfig` (Windows) or `ifconfig` (macOS/Linux), and
> keep both devices on the same network.

## Environment variables

Expo only exposes variables prefixed `EXPO_PUBLIC_`, and they are **inlined
into the bundle at build time** — they are visible to anyone with the app, so
never put a secret in one. `.env*` files are gitignored.

| Variable | Required | Notes |
| --- | --- | --- |
| `EXPO_PUBLIC_API_URL` | yes | API base URL |
| `EXPO_PUBLIC_WEB_APP_URL` | no | Target of the "More on the web" link. Falls back to `http://localhost:3000/home` |

EAS build profiles set these per environment — see `eas.json`.

## Scripts

| Command | Does |
| --- | --- |
| `npm start` | Expo dev server (Expo Go) |
| `npm run android` | Native Android build and run — needs Android Studio |
| `npm run ios` | Native iOS build and run — needs Xcode (macOS only) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint — **required**, see below |
| `npm test` | Jest, single run — what CI runs |
| `npm run test:watch` | Jest in watch mode |

> **Always run `npm run lint`.** This repo's `tsconfig` does not set
> `noUnusedLocals`, so unused imports pass `tsc` and fail ESLint — and CI runs
> `npm run lint`. Typecheck plus tests is not enough here.

## Testing

Jest (`jest-expo` preset) + React Native Testing Library, with API modules
mocked. Tests are **colocated** with the file they cover.

```bash
npm test
```

Things that catch people out:

- `render()` returns a **Promise** — always `await render(...)`.
- Mock API modules with an **explicit factory**, not a bare automock. A bare
  automock loads the real `apiInterceptor.ts`, whose `axios.create()` crashes
  under jest-expo.
- Screens using `useFocusEffect` need it mocked, or a `NavigationContainer`.
  Jest hoists mock factories above imports, so `require()` inside the factory
  and prefix any outer variable with `mock`.

**jest-expo runs on Node's full-ICU V8, not Hermes.** A green test run does not
prove currency and date formatting work on a device — check those on real
hardware.

## Builds and releases

EAS profiles: `development`, `preview`, `production` (see `eas.json`).

> **Release signing:** the production Android build must be signed with the
> project's existing release keystore. Signing a Play Store update with a
> different key — including one EAS generates for you — produces an APK/AAB the
> store will reject, because the signature no longer matches the installed app.
> Confirm which credential a release build is using before shipping it.

## Compatibility with the API

**Published builds cannot be force-upgraded.** Someone is always running last
release's binary against today's API, so backend changes stay additive and this
app must tolerate response fields it does not recognise.

Before pushing a dependency change, confirm the lock file still satisfies CI's
npm:

```bash
npx -y npm@10 ci --dry-run
```
